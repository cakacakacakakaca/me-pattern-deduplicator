# ME网络样板去重器 1.1.0

独立 Minecraft 1.20.1 Forge / AE2 附属模组，不依赖 GTLCore 或 GTL Pattern Port。

下载 [me-pattern-deduplicator-1.20.1-1.1.0.jar](https://github.com/cakacakacakakaca/me-pattern-deduplicator/releases/tag/v1.1.0)。

## 安装

关闭游戏，用 `me-pattern-deduplicator-1.20.1-1.1.0.jar` 替换旧版去重器 JAR，不能同时保留 1.0.0。多人游戏客户端和服务器都要更新为同一版本；1.1.0 的通信协议与 1.0.0 不兼容。

依赖 Minecraft 1.20.1、Forge 47.1.47 或更新的 47.x、AE2 15.4.10 系列。GTLE 3.9.2 已包含这些依赖。

物品：`mepatterndedupe:me_pattern_deduplicator`（ME网络样板去重器），位于创造模式工具分类，也可通过 JEI 查找或使用：

```
/give @s mepatterndedupe:me_pattern_deduplicator
```

合成配方保持不变：顶部中央赛特斯石英晶体，中间 AE2 网络工具、左右空白样板，底部中央逻辑处理器。

## 使用

1. 主手持工具，对 ME 电缆可连接面 Shift + 右键绑定。首次未绑定时直接右键电缆也可以绑定并打开。
2. 右键打开，保持在绑定点同维度、64 格内，网络需有电。
3. 每个主产物是一项标题，所有相关样板直接列在标题下面。合成、处理样板都参与比较，不论是否位于同一供应器或样板总成。
4. 子项显示样板类型、产出数量及输入图标。物品、流体均使用真实图标；输入过多会在本行内自动换行。蓝色角标表示某个输入的替代材料，替代项也直接显示。悬停可查看完整名称、精确数量、mB、材料 ID 和所属输入序号。简写 k/M/G 只用于显示，比较始终使用精确数量。
5. 设备名称、坐标、槽号及输入方案编号在空间允许时与图标并排显示；悬停行可查看完整信息。
6. 点击任意样板行勾选/取消，可以多选；点击主产物标题切换该组当前搜索结果的选择。“全选结果”选择全部搜索结果，不限于屏幕内的行；搜索后隐藏的已选项仍保留，需要时使用“清空选择”。底部始终显示选择总数。
7. “批量销毁”弹出一次确认。**每个选中的物理槽销毁 1 个编码样板，返还 1 个空白样板至 ME 存储**。允许选择整组，因此请在确认前检查选择。
8. 只选择一个槽时，可以使用“取出一个”，把完整编码样板放入玩家物品栏。
9. 全部结果位于同一个连续列表。使用鼠标滚轮或拖动右侧滚动条；搜索框没有焦点时也可使用 Home/End、PageUp/PageDown。没有翻页按钮，也没有输入详情二级页面。
10. “重扫”用于同步其他玩家或设备后来新增、移除、更改的样板。“异常”在同一滚动列表顶部展开扫描异常，最多显示前 1,000 条。

搜索支持主产物名称、ID、设备名称、维度和坐标。结果闲置 10 分钟会过期。

## 判定规则

- 同主产物指 AEKey 身份完全相同，包含物品/流体 ID 和相关 NBT 数据；忽略副产物和主产物产出数量。
- 输入比较包含身份、数据、数量、流体量、替代输入以及首选材料；忽略输入槽顺序，并合计等价的拆分数量。
- 只有同一主产物出现两种或更多不同输入方案时才显示。纯粹复制相同输入、仅副产物不同的样板不会误报。
- 一个冲突组中的所有物理槽都会保留，包括同一供应器中的多个槽、多个供应器中相同配方的副本。缓存只避免重复计算，不会合并或遗漏实际样板槽。

## 1.1.0 性能改动

旧版每游戏刻最多检查 128 个槽，空槽同样消耗额度；大型、稀疏的样板总成因此需要等待很久。

新版取消槽数限速，以每游戏刻约 35 ms 的时间预算扫描，批量检查时间。通过设备的 ICraftingProvider 接口复用已解码样板，按完整编码物品身份缓存输入特征；缓存缺失时仍使用 AE2 解码器。实际库存仍逐槽读取，不使用会丢失重复槽的合成配方汇总表。

分组采用散列表，移除全量样板排序和重复分组。结果中物品/流体键、配方和设备信息采用字典共享，按 24 KiB 分块传送。选择列表按每包最多 1,024 个行号发送，避免大批量选择触发单包长度限制。结果总长度上限 64 MiB，超出会明确报错，不静默丢弃记录。

界面完整保留结果，但通过位置索引仅绘制当前可见行，不会创建几万个按钮。销毁后根据已扫描记录更新分组，不再重新遍历网络或重新解码全部样板。

## 操作一致性

操作在服务器主线程进行。客户端只能发送会话和行号，不能指定物品 NBT。服务器逐项复核工具、绑定网络、设备在线状态、位置权限和源槽完整内容；被其他玩家或机器改动的槽会拒绝旧操作。

批量操作按时间预算执行，成功与失败分别计数；不是整批原子事务。ME 不能接收空白样板、槽位变化、设备离线等情况下跳过对应项。先模拟接收，再取出，再实际接收；接收失败尝试回填原编码样板。空白样板只进入 ME 存储。极端情况下第三方设备在同步回调中占用了原槽且无法恢复，返还玩家的是原编码样板。

批量销毁允许清空一个组，不自动替玩家保留某个配方。操作完成后，如果一个组只剩同一种输入方案，会从冲突列表消失，但剩下的样板不会被额外移除。外部变化需要手动重扫；每次执行操作仍会检查所选槽是否与扫描时一致。

关闭工具会停止后续尚未处理的项，已经完成的项不会撤销。不会取消玩家已经提交的合成任务。

## 扫描范围

读取当前 ME 网络中已加载、公开 AE2 PatternContainer 库存的设备。支持普通、面板式 AE2 样板供应器；GTLE 3.9.2 的 GTLCore 1.2.3.3-fix4 MEPatternBufferPartMachine 通过相同接口接入，无需直接依赖 GTLCore。

不会强制加载区块、不扫描子网或 ME 存储中的备用编码样板。无法公开编辑库存的虚拟供应器会报告异常。有世界位置且在线的设备才允许修改。第三方动态样板的兼容程度取决于其 AE2 接口信息。

## 验证与性能范围

独立基准使用 5 万个真实 AE2 处理样板、25 万个库存槽位。复用设备的已解码配方时，扫描及分组约 0.33 秒。结果编码和读取计入后约 0.47 秒。整合包里的实际时间取决于设备、配方和服务器负载。游戏内状态栏会显示实际扫描耗时，日志有 `ME dedupe:` 记录，可用于核对整合包中的结果。

已运行独立 Forge / AE2 启动检查、真实处理样板与库存检查、输入分组与事务回退测试，并启动真实 Minecraft 客户端检查分组、图标、多选和 5 万行滚动。尚未在玩家 GTLE 存档中完成整网扫描及 ME 批量返还的端到端测试。

## 从源码构建

JDK 17，执行 `gradlew.bat build` 或 `sh gradlew build`。首次构建需下载 Gradle、Forge 和 AE2 依赖，产物位于 `build/libs`。

`logicTest` 随 build 执行。开发环境可使用 `-Pae2MappedJar=路径` 指定 Mojang 开发映射的 AE2 JAR；不能用生产 JAR 代替。独立测试：`runData -Psmoke=true -Pae2MappedJar=路径 -PguideMappedJar=路径`。界面测试：`runClient -Ppreview=true -Pae2MappedJar=路径 -PguideMappedJar=路径`，测试数据不读取或修改玩家世界，截图位于 `build/preview-run/screenshots`。

测试类不打入生产 JAR。源码 MIT 许可，AE2、Forge、Minecraft 资源遵循各自许可。
